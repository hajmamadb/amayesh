## بخش ۷ — مدل داده و قواعد تجمیع

### ۷.۱. ساختار سه‌لایه اصلی

#### لایه ۱ — موجودیت فضایی (`regions`)

| فیلد | نوع | توضیح |
|---|---|---|
| `id` | UUID | شناسه یکتا |
| `parent_id` | UUID | ارجاع به والد |
| `level` | Enum | province / county / district / city / rural_district / village |
| `official_code` | String | کد رسمی تقسیمات کشوری |
| `geometry` | Geometry | مرز مکانی |
| `valid_from` / `valid_to` | Date | تاریخ اعتبار |

#### لایه ۲ — تعریف شاخص (`indicators`)

| فیلد | نوع | توضیح |
|---|---|---|
| `code` | String | کد یکتا (مثلاً D12.01.03) |
| `domain` | Enum | D1 تا D12 |
| `min_level` | Enum | حداقل سطح معتبر |
| `aggregation_method` | Enum | sum / weighted_avg / avg / ratio / max / min / n.a. |
| `data_type` | Enum | registery / survey / estimated / media / infrastructure / performance |
| `sensitivity` | Enum | public / restricted / confidential |
| `threshold_source` | String | مرجع تعیین آستانه هشدار |

#### لایه ۳ — مشاهده (`observations`)

| فیلد | نوع | توضیح |
|---|---|---|
| `region_id` | UUID | ارجاع به منطقه |
| `indicator_id` | UUID | ارجاع به شاخص |
| `time_period` | Date/Interval | دوره زمانی |
| `value` | Numeric | مقدار |
| `source_id` | UUID | ارجاع به منبع |
| `quality_flag` | Enum | verified / provisional / estimated / flagged / media-signal |
| `urban_rural_split` | Enum | urban / rural / total |

---

### ۷.۲. جداول پشتیبان

**جدول `sources`** (منابع داده): شامل منبع، نهاد تولیدکننده، روش سنجش، تاریخ.

**جدول `region_zone_membership`** (اتصال به لایه‌های عرضی): اتصال هر منطقه به حوضه آبخیز، منطقه برنامه‌ریزی، پهنه همگن.

**جدول `indicator_composite`** (تعریف شاخص‌های ترکیبی): وزن‌ها و اجزای هر شاخص ترکیبی.

**جدول `audit_log`** (ردیابی تغییرات): هر تغییر در مقدار، منبع یا تعریف شاخص.

**جداول ویژه D12:** `facilities`, `facility_service_area`, `facility_flows`, `spatial_validation_rules` (به فایل ۸ مراجعه شود).

---

### ۷.۳. قواعد تجمیع

| نوع شاخص | روش تجمیع | مثال |
|---|---|---|
| شمارشی | جمع | تعداد مسجد، تعداد شعبه فروشگاه زنجیره‌ای |
| نسبتی | میانگین وزنی بر پایه مخرج | سرانه فضای مذهبی، نرخ باسوادی |
| زیرساختی بولی | حداکثر (وجود/عدم وجود) | وجود سینما، وجود مرکز دفع زباله |
| فاصله‌ای | حداقل | فاصله تا نزدیک‌ترین مرکز آموزشی |
| عملکردی (ظرفیت) | جمع | ظرفیت انبار، ظرفیت پذیرش رستوران |
| شاخص ترکیبی | محاسبه مجدد در سطح هدف | سطح توسعه‌یافتگی، دسترسی‌پذیری چندوجهی |
| جریان | ماتریس مبدأ–مقصد یا جریان خالص | مهاجرت، جریان بار مراکز لجستیک |

**قاعده ویژه D12:** شاخص‌های «وجود/نوع مکان» با **حداکثر** تجمیع می‌شوند (اگر یک آبادی خانه بهداشت دارد، دهستان نیز «دارد» تلقی می‌شود)، اما شاخص‌های «ظرفیت» و «تعداد» با **جمع** تجمیع می‌شوند. تفکیک این دو نوع در تعریف شاخص الزامی است.

**هشدار طراحی:** تجمیع شاخص‌های نسبتی با «میانگین ساده» خطای سیستماتیک ایجاد می‌کند؛ همیشه باید وزن بر پایه مخرج (جمعیت، خانوار، شاغلان) اعمال شود.

## بخش ۸ — کیفیت داده و اعتبارسنجی

### ۸.۱. پرچم‌های کیفیت

- **verified:** داده ثبتی تأییدشده توسط نهاد متولی.
- **provisional:** داده اولیه، در انتظار تأیید.
- **estimated:** برآورد مدل‌سازی یا درون‌یابی.
- **flagged:** داده مشکوک یا نیازمند بازبینی.
- **media-signal:** سیگنال رسانه‌ای، غیرقابل استفاده به‌عنوان آمار رسمی.
- **performance-survey:** داده عملکردی حاصل پیمایش میدانی (برای اماکن).

### ۸.۲. سلسله‌مراتب اعتبار در نمایش

داشبورد موظف است هنگام نمایش شاخص در سطحی پایین‌تر از `min_level`، هشدار «اعتبار محدود» نمایش دهد. این قاعده به‌ویژه برای شاخص‌های پیمایشی D7–D10 و شاخص‌های عملکردی D12 (که ممکن است فقط برای یک نمونه از اماکن اندازه‌گیری شده باشند) اهمیت دارد.

### ۸.۳. کنترل کم‌گزارشی و حساسیت

برای شاخص‌های حساس (خودکشی، همسرآزاری، کودک‌آزاری، اعتیاد، اماکن نظامی)، ضریب تصحیح کم‌گزارشی یا سطح دسترسی باید توسط متخصص تعیین و در جدول `indicators` ثبت شود. داده سطح آبادی برای این شاخص‌ها فقط در محیط تحلیل داخلی قابل مشاهده است.

### ۸.۴. اعتبارسنجی مکانی اماکن

برای اماکن جدید (به‌ویژه در D12)، سامانه باید **قواعد اعتبارسنجی مکانی** را اجرا کند: مثلاً آیا فاصله آرامستان از محدوده شهری کمتر از ۱۰ کیلومتر است؟ آیا مرکز لجستیک در پهنه مجاز زیست‌محیطی قرار دارد؟ آیا مکان نظامی حداقل ۲۰ کیلومتر از مرکز جمعیتی فاصله دارد؟ این قواعد از اسناد و ضوابط رسمی استخراج و به‌صورت قواعد قابل اجرا در پایگاه داده ذخیره می‌شوند.

### ۸.۵. نسخه‌بندی و ردیابی

هر تغییر در مقدار، منبع یا تعریف شاخص باید در `audit_log` ثبت شود تا سری‌های زمانی قابل بازتولید باشند.

## بخش ۷.۴ — نمونه کوئری‌های PostGIS برای D12

### محاسبه فاصله تا نزدیک‌ترین مرکز آموزشی

```sql
SELECT v.id AS village_id, v.name,
       MIN(ST_Distance(v.geometry::geography, f.geometry::geography)) / 1000 AS distance_km
FROM regions v
JOIN facilities f ON f.facility_type IN ('school', 'high_school')
WHERE v.level = 'village'
GROUP BY v.id, v.name;
