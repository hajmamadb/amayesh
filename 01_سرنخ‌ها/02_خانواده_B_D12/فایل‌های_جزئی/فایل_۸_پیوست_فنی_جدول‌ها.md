### د.۳. جدول `facility_flows` (جریان‌های عملکردی)

| فیلد | نوع | توضیح |
|---|---|---|
| `flow_id` | UUID | شناسه جریان |
| `facility_id` | UUID | ارجاع به مکان |
| `flow_type` | Enum | `cargo_in`, `cargo_out`, `visitors`, `transactions` |
| `volume` | Numeric | حجم جریان |

| `time_period` | Interval | دوره (روزانه، ماهانه، سالانه) |
| `origin_region_id` | UUID | مبدأ (برای جریان‌های کالا و جمعیت) |
| `destination_region_id` | UUID | مقصد |
| `peak_time` | Time | زمان اوج جریان |
| `source_id` | UUID | منبع داده |

**قاعده ثبت:** برای جلوگیری از دوباره‌شماری، هر جریان باید یا با `origin_region_id` و `destination_region_id` ثبت شود، یا به‌صورت خالص (خالص ورودی منهای خروجی). ثبت هم‌زمان جریان خام و خالص ممنوع است.

## پیوست و — معماری فنی پیشنهادی

### و.۱. لایه ذخیره‌سازی

پایگاه داده **PostgreSQL** با افزونه **PostGIS** برای ذخیره‌سازی و تحلیل داده‌های مکانی. PostGIS امکان محاسبه فواصل، هم‌پوشانی، حرایم و تحلیل‌های شبکه‌ای را در سطح پایگاه داده فراهم می‌کند.

**افزونه‌های ضروری:**
- `postgis` — انواع داده هندسی و توابع تحلیلی
- `pgrouting` — تحلیل شبکه‌ای (کوتاه‌ترین مسیر، زمان سفر)
- `postgis_raster` — داده‌های رستری (در صورت نیاز)
- `pg_trgm` — جستجوی متنی

### و.۲. لایه پردازش تحلیل مکانی

استفاده از توابع تحلیلی PostGIS:
- `ST_Distance` — محاسبه فاصله (برای حرایم)
- `ST_Intersects` — هم‌پوشانی (برای پهنه‌های مجاز)
- `ST_Buffer` — شعاع دسترسی
- `ST_Within` — قرارگیری در پهنه
- `ST_Area` — مساحت
- `ST_Transform` — تبدیل سیستم تصویر

### و.۳. لایه API

طراحی **RESTful API** برای دسترسی به داده‌ها و شاخص‌ها، با:
- احراز هویت مبتنی بر نقش (RBAC)
- توکن JWT با انقضای محدود
- کنترل دسترسی به داده‌های `restricted` و `confidential`
- Rate limiting
- Logging کامل درخواست‌ها
